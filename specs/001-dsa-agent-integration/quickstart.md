# Quickstart: DSA × PlatformAgent Integration

**Branch**: `001-dsa-agent-integration` | **Date**: 2026-04-17

Run the combined app end-to-end against a live database in ~20 minutes. This doc targets a developer picking up the feature branch cold.

---

## Prerequisites

- `aws-cli` v2, logged in as `AdministratorAccess-637119802057`
- `uv` (≥0.4), Docker, `psql`, `git`
- Terraform ≥1.5
- Node 20+ (for local Vite dev)
- An unused `.env` at repo root (will be generated by bootstrap)

---

## 1. Check out the feature branch

```bash
cd /Users/mwebb/Projects/dsa-platform
git fetch origin
git checkout 001-dsa-agent-integration
```

## 2. Provision demo databases

```bash
./scripts/bootstrap.sh --services rds,redshift --profile AdministratorAccess-637119802057
# Writes .env with DB_* (PostgreSQL) and RS_* (Redshift) vars, seeds Northwinds into both.
source .env
```

Snowflake SSO requires no bootstrap — the `SF_*` block in `.env.example` points at the existing Pinnacle Financial demo.

## 3. Install Python + frontend deps

```bash
uv pip install -e ".[dev,redshift,snowflake]"
cd frontend && npm install && cd ..
```

## 4. Start the backend (FastAPI + Strands agent) locally

```bash
# From repo root
uv run uvicorn platform_agent.api.app:app --host 0.0.0.0 --port 8080 --reload
```

Verify:
```bash
curl http://localhost:8080/health
# => {"status":"ok","build":"…","mode":"local"}
```

## 5. Start the frontend dev server

```bash
cd frontend
npm run dev
# => http://localhost:5173
```

Open `http://localhost:5173` in a browser. The app loads in Dark theme (default per Constitution Article V). A demo-mode toggle sits in the top bar; leave it off.

## 6. Walk through the 4-step workflow

### Step 1 — Requirements

1. Click "Connect to source database" in the sidebar.
2. Choose **PostgreSQL**. Fill in host/port/db/user/password from `.env` (`DB_HOST`, `DB_PORT`, etc.).
3. Connection status pill turns green. Open Step 1.
4. Type `We want to understand our order data` into the chat.
5. Expected (within ~30s): the PRD artifact panel populates with sections that cite real Northwinds tables (`public.orders`, `public.customers`, `public.order_details`). Chat narrates.
6. Approve the gate.

### Step 2 — Conceptual Model

1. Type `Propose the core entities and relationships`.
2. Expected: the ERD renders with entities `Orders`, `Customers`, `Order Details`, `Products`, etc., with real FK edges.
3. Approve the gate.

### Step 3 — Logical Model

1. Type `Build the logical model for a fct_orders mart with date, customer, and product dimensions`.
2. Expected: table rows populate with real column types sourced from `information_schema.columns`, and each field shows up to 5 sample values fetched live.
3. Approve the gate.

### Step 4 — Detailed Requirements

1. Type `Generate the dbt project and semantic layer`.
2. Expected: progress events show `generate_dbt_project` and `generate_semantic_layer` tool calls.
3. An `artifact_ready` event fires; the browser initiates a zip download within 60 seconds.
4. Unzip locally:
   ```bash
   unzip ~/Downloads/northwinds-dw-*.zip -d /tmp/dbt_check
   cd /tmp/dbt_check/*
   uv run dbt compile --profiles-dir .
   # Expected: Compiled successfully, NN models
   ```

## 7. Exercise demo mode

1. Toggle "Demo mode" in the top bar.
2. Notice the demo badge appears on every artifact panel.
3. Repeat Steps 1–4. All content is synthesised from `frontend/src/data/mock/`; no backend calls occur.
4. Open DevTools Network; confirm zero requests to `:8080`.

## 8. Verify existing interfaces still work

```bash
# Streamlit
uv run streamlit run streamlit_app/app.py --server.port 8501
# Visit http://localhost:8501 — connect to Northwinds PostgreSQL, ask a schema question.

# CLI agent
uv run python -m platform_agent --profile $AWS_PROFILE
# Ask: "What tables are in the database?" — agent should respond.
```

Both MUST succeed unchanged (FR-003, SC-006).

## 9. Run tests

```bash
uv run pytest tests/contract tests/integration -q
```

Expected: all tests pass. Integration tests expect the `DB_*` env vars from step 2 to be present.

## 10. Deploy (optional)

```bash
cd infra-terraform
terraform plan   # Expected: minimal plan — env vars only; no module adds.
terraform apply
```

After apply, the Amplify app URL should serve the combined UI. Sign in with Cognito; run the same Step 1–4 workflow against whatever RDS/Redshift instance the deployment has configured.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `X-DSA-Session-ID` missing | Close and reopen the browser tab; `session.ts` mints on mount. |
| 30s silence → error | Backend heartbeat emitter not wired. Check `src/platform_agent/api/sse.py`. |
| Zip download 404 | Handle expired (60s TTL). Re-run Step 4. |
| Streamlit can't connect | `scripts/bootstrap.sh` may have not run `--services rds`. Rerun. |
| CORS preflight fails | Ensure `http://localhost:5173` is in FastAPI's CORS allowlist. |
